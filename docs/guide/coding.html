Skill Card B

🧩 The Coding Blocks

Fifteen blocks, three families, five each. No typing except the words you choose. Works on anything in any world — including whatever you just built.

Getting there: click any object and choose Program. The palette is on the left, your stack goes on the right. Drag a block across, drop it into the mouth of another block to nest it, and press Save. It starts immediately.

All fifteen blocks

Three families, five blocks each. The colour on this card is the colour in the app.

C

Control

When and how often things happen

  1. repeat 10 times
  2. forever
  3. wait 1 seconds
  4. when an object says hello
  5. duplicate 4 ft away

💡 repeat, forever and when an object says all have a mouth — whatever you drop inside is what runs. when an object says does not run when you press play: it sits and waits until something, anywhere in the world, uses a say block with that exact word. That is how you make two objects work together. duplicate is the odd one out — it is the only block whose effect leaves the object it is written on.

M

Motion

Where things go

  1. move forward 2 feet
  2. move up by 1 feet
  3. glide 10 feet over 2 seconds
  4. rotate 15 degrees
  5. go back to start

💡 move forward and glide follow the way the object is pointing, so a rotate before them genuinely steers. move up is the exception — up is up whichever way a thing is facing, and a negative number goes down. The difference between the two travel blocks is time: move forward arrives instantly, glide takes the seconds you give it. go back to start undoes everything at once — position, turn and size — which is the block to reach for when a program has made a mess.

L

Looks

What things look like — and what they say

  1. say hello
  2. change size by 10 %
  3. set size to 100 %
  4. set opacity to 100 %
  5. change color to ▦

💡 change size by is relative and it compounds: +10% twenty times over is not double, it is about 6.7 times bigger, and +10% then −10% does not take you back where you started. set size to is absolute — it always measures from the size the object was when the program started, so set size to 100% is always "back to normal". Put set size to 50% inside a forever and nothing runs away; put change size by −50% there and the object is gone in a second. set opacity to 0% makes something invisible without deleting it.

Try these four

  1. Drive round a square

    Four sides, four right turns. 360 divided by 4 is 90, so it finishes exactly where it began — change the 4 and the 90 together and you can drive any shape you like.

    1. repeat 4 times
    2. move forward 10 feet
    3. wait 0.5 seconds
    4. rotate 90 degrees

  2. A slow heartbeat

    Out to 115% and back to normal, forever. Because set size to measures from where it started, this beats steadily instead of drifting bigger every time round.

    1. forever
    2. set size to 115 %
    3. wait 0.4 seconds
    4. set size to 100 %
    5. wait 0.4 seconds

  3. Two objects, one signal

    The first three blocks go on one object. The last two go on a different one — it sits and waits until it hears the word. This is how you get things to happen in order across the world instead of each object doing its own thing.

    1. say go
    2. wait 2 seconds
    3. say stop
    4. when an object says go
    5. glide 20 feet over 3 seconds

  4. A crowd of one thing

    Build a model, then let it copy itself into a row. Each copy lands one step further out.

    1. repeat 5 times
    2. duplicate 5 ft away

🤯 Worth knowing

A copy made by duplicate inherits the whole program except the duplicate block itself. That is on purpose: without it, forever → duplicate would double the world every few frames and fill it in about four seconds. A spinning robot still makes spinning copies — they simply do not breed.

Block colours

  • Control — repeat, forever, wait, when an object says, duplicate
  • Motion — move forward, move up, glide, rotate, go back to start
  • Looks — say, change size, set size, set opacity, change colour

One rule that catches everybody: the difference between by and to. change size by is a nudge from wherever the object is now, so it compounds and never quite comes back; set size to is a destination measured from where the object started, so 100% always means normal. It is the same idea as move forward versus go back to start — one is a step, the other is a place. Nearly every program that "runs away" is a by block where a to block was meant.

If you have used these cards before: the old move X, move Y and move Z blocks have left the palette. They slid an object along the world's directions, so turning something never changed where it then travelled and you could not drive in a circle at all. move forward and glide follow the object's own facing instead, which is why a square is now four blocks long. Any program you already saved with the old blocks still runs exactly as it did — they were retired, not deleted.
