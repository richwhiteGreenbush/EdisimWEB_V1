🔒 Student privacy

Edusim collects nothing about your students

No accounts. No logins. No names, no email addresses, no class codes, no parental consent forms. Not because we promise not to look — because there is nothing to look at. This page says exactly what happens to data when a child opens Edusim, in plain language, with no exceptions hidden further down.

📋 The one-page IT brief

The short version

Edusim is a web page. A student opens it and is immediately building — there is no sign-up step, because there is no account system to sign up to. Their work is saved by the browser, on their own device, in the same way a browser remembers the settings of any website. It is never uploaded anywhere, and nobody else can reach it.

This is an architectural fact, not a policy choice. Edusim has no server that stores student work, no user table, and no way to associate anything a student does with a person. A promise not to collect data can be changed by editing a document; a product with nowhere to put the data cannot.

  • Does a student need an account?No. There is no account system at all — not for students, not for teachers, not optionally.
  • Do you ask for a name, email address or age?No. Edusim has no field anywhere that asks a child for anything about themselves.
  • Where is a student’s work stored?In their own browser, on their own device, using the browser’s built-in storage (IndexedDB). It never leaves the machine unless the student chooses to export a file.
  • Can a teacher see what a student built?Only if the student hands it to them. Save World exports a file the student can email, drop in a shared folder, or hand in however your school already hands work in.
  • Is there chat, messaging or any way to contact another user?No. There are no other users. Edusim is single-player by design and there is nothing in it that connects one child to another.
  • Are there advertisements?None, anywhere, ever. There is no advertising network on this site or in the app, and no plan for one.
  • Is anything sold, shared or licensed to a third party?Nothing is collected, so there is nothing that could be. There is no data-sharing arrangement with anyone.
  • Is there a paid tier that changes any of this?No. Edusim is free, with no upgrade, no trial that expires, and no premium version that behaves differently.

What the website itself records

We do count how many people open these pages, because we cannot improve a resource nobody can measure. That counting is deliberately built so it cannot become surveillance, and it is worth stating exactly how, because “we use privacy-friendly analytics” is a sentence every site says.

It runs on our own server

No Google Analytics, no third-party analytics product, no tracking script of any kind. The count is recorded by this site, on this site’s own server.

No cookies, no identifiers

Edusim sets no tracking cookies at all. Nothing stored in your browser by the counter can identify you, and nothing is sent that could be used to recognise you on a later visit.

No IP addresses are stored

Your IP address is not written to any file or database. The server sees it to answer the request, as every web server must, and then it is gone.

Only totals exist

What is stored is of the form “the lesson-plans page was opened 41 times on 6 September.” There is no record of individual visits, so a session cannot be reconstructed by us or by anybody else.

Do Not Track is honoured

If your browser sends Do Not Track or Global Privacy Control, nothing is counted at all — not anonymously, not in aggregate. The request is simply never made.

The web server keeps standard logs

Like every web server on the internet, the hosting provider writes ordinary access logs. Those are the host’s, are not used for analytics, and are not connected to anything in Edusim.

The one third party on this site, stated plainly. These pages load their typefaces from Google Fonts, so opening a page here makes one request to fonts.googleapis.com and fonts.gstatic.com, which Google sees. That is the only off-site request the website makes, it carries no information about the visitor beyond what any web request carries, and the Edusim app itself loads no fonts and makes no third-party requests whatsoever. We name it here rather than round it down to zero, because a privacy page that quietly omits its one exception is not worth reading.

The two places a student can reach the wider internet

Edusim has two features that put real web content inside a world. Neither collects anything, and both are worth knowing about before a class uses them, because what they load is not ours.

Web browser panels

A student can place a panel in the world that displays a live web page, and type an address into it. That page is loaded directly by the student’s browser, exactly as if they had opened a new tab — so whatever your school’s content filter already does to a browser tab, it does to a panel. Edusim does not proxy the request, cannot see it, and records nothing about it.

YouTube video panels

A student can paste a YouTube link and get the video as a panel in the world. The video is served by YouTube and is subject to YouTube’s own terms and to whatever your district already permits. If YouTube is blocked on your network, the panel is blank — nothing else changes.

Every such link is rewritten to www.youtube-nocookie.com before the panel is built, whichever form of YouTube address the student pasted. That is YouTube’s privacy-enhanced host: it serves the same video without setting personalisation cookies unless the video is played. It is not a complete protection — YouTube still sees the request — and we prefer to describe it accurately than to imply more.

If you want neither feature in a lesson, simply do not teach them. They live behind Menu ▸ Create Model ▸ Load Object and nothing in Edusim opens a web page on its own. Every one of the built-in worlds also contains one information panel that opens a page from this site.

Sharing a world to the World Database

The one place a student can send something to us is the World Database, where a world can be published for other people to open. This is entirely optional, it is never automatic, and it takes a deliberate multi-step action.

What a shared world carries, and nothing else:

  • A first name or nickname, typed by whoever shares it. Teachers should tell students to use a first name only, or a made-up one — the field is free text and we cannot enforce it.
  • An optional class or group name, such as “Mrs Álvarez, Grade 4”.
  • A description and a screenshot of the world, both supplied by the sharer.
  • The world file itself — the 3D objects, nothing more.

No email address is asked for and none is stored. The submitter’s IP address is stored only as a one-way hash, so that a flood of automated submissions can be stopped without the database holding an address in the clear. Whoever shares a world is given a key that lets them take it down again later, and that key is stored only as a hash too — nobody, including us, can look it up for them.

Teachers can turn sharing off entirely, or require approval. A school running its own copy can set moderation so every shared world waits for a teacher to approve it. If you would like a world taken down from ours, ask — there is no form and no argument.

Where Edusim sits in the law

We are not offering legal advice, and your district counsel is the right person to make the determination. What we can do is state the facts your review will ask for.

  • COPPA governs the collection of personal information from children under 13. Edusim collects no personal information from anyone, of any age.
  • FERPA governs education records. Edusim creates no education records: student work never reaches us, and there is no record connecting work to a student.
  • State student-privacy laws and the Student Privacy Pledge are typically about what a vendor does with student data it holds. Edusim holds none.
  • GDPR and UK GDPR concern personal data. The website processes none beyond ordinary server logs held by the host, and the app processes none at all.

Because there is no account, no roster and no data transfer, there is generally no data-processing agreement to sign — which is precisely why a teacher can use Edusim on a Tuesday without a purchase order or an IT ticket. If your district requires a signed document regardless of what a tool collects, ask and we will work through it with you.

Verifying any of this yourself

Every claim on this page is checkable without taking our word for it. Edusim’s entire source code is public, and the network tab of your own browser’s developer tools will show you every request the app makes while a student uses it — which, with the two panel features unused, is the app’s own files and nothing else.
