There is nothing to install, provision or approve

Everything a school technology department needs to decide about Edusim, on one page. Written to be forwarded without editing, and short enough to be read in a corridor.

🔒 The full privacy page

What it is

Edusim: Web Edition is a static web page that renders 3D graphics with WebGL. There is no installer, no extension, no plug-in, no runtime and no client software of any kind. A student opens a URL and is building. It is made at the Greenbush Southeast Kansas Education Service Center and is free, with no paid tier.

What to allowlist

If your filter works on an allowlist rather than a blocklist, these are the hosts Edusim needs. There are three, and only the first is required.

  • edusim3dweb.com — the app, the world gallery, the lesson plans and this page. Required.
  • fonts.googleapis.com and fonts.gstatic.com — typefaces for the website pages. Optional: blocked, the pages render in a system font and everything still works. The app itself loads no fonts.
  • www.youtube-nocookie.com — only if you want students to be able to place a YouTube video panel inside a world. Blocked, that one feature shows an empty panel and nothing else changes.

Content filtering keeps working exactly as it does now. Edusim can place a panel in a world that shows a live web page, and that page is fetched by the student’s own browser as an ordinary request — it is not proxied through us and it is not tunnelled. Whatever your filter does to a browser tab, it does to a panel. Nothing in Edusim can be used to reach a site your filter blocks.

What it needs from a device

  • A browser with WebGLChrome, Edge, Firefox and Safari from roughly 2020 onward. WebGL is on by default in every managed ChromeOS build; if a policy has disabled hardware acceleration, Edusim will run slowly or not at all, and that is the single most likely cause of a problem report.
  • Browser storage on the deviceStudent work is saved with IndexedDB, in the browser, on the machine. If site data is blocked by policy, Edusim still runs perfectly — work simply does not persist between sessions, and students should export a file at the end of the period.
  • Nothing elseNo microphone, no camera, no location, no clipboard access, no notifications, no local file-system access beyond an ordinary file picker when a student chooses to open or save a world file.

Ephemeral mode is worth calling out, because it is where several competing 3D tools fail. Edusim runs normally on a device that wipes itself at sign-out; the only consequence is that work does not survive the wipe, so a class on ephemeral devices should end with Save World and a handed-in file. No configuration change is needed to make this work.

Privacy, in one paragraph

Edusim collects nothing about students. There are no accounts, so there is no user record; work is stored by the browser on the device and is never uploaded. The website counts page views on its own server with no cookies, no identifiers and no IP addresses stored, honours Do Not Track and Global Privacy Control, and loads no third-party analytics or advertising script of any kind. Because nothing is collected, there is nothing to breach, sell, subpoena or retain. The full privacy page states every exception, including the one third-party request the website makes.

COPPA: no personal information is collected from anyone, of any age. FERPA: no education records are created — student work never reaches us. Your district counsel makes the determination; these are the facts the review will ask for.

What it does not do

Stated plainly, because discovering a missing feature in week three is worse than being told about it now.

  • No single sign-on. No Clever, no ClassLink, no Google or Microsoft sign-in — there is nothing to sign in to.
  • No rostering, dashboard or gradebook. Teachers see student work when a student hands in a file.
  • No cross-device save. Work lives on the device it was made on, or in a file the student carries.
  • No chat, messaging or multiplayer. There is no way for one student to contact another, by design.

Every one of these is a consequence of having no accounts, and having no accounts is what lets a teacher use Edusim tomorrow morning without a purchase order, a consent form or a ticket to you.

Testing it yourself

  1. Open edusim3dweb.com/app/ on a managed student device.
  2. You should be standing in a park within a few seconds. Walk with the arrow keys.
  3. Open Menu ▸ Create Model and place a cube. That is the whole onboarding.
  4. Watch the network tab if you want to confirm what is and is not requested.

If it does not load, the cause is almost always hardware acceleration disabled by policy or the domain blocked at the filter. Both are visible in the browser console immediately.
